## 1. 배경과 문제

| 현재 (정적 가이드) | 문제 |
|---|---|
| PDF/웹 매뉴얼로 규칙을 "읽기"만 함 | 규칙 해석이 디자이너·국가·협력사마다 달라짐 |
| 패키지 검수를 사람이 눈으로 비교 | 신규 SKU·국가가 늘수록 검수 시간과 누락 증가 |
| 로컬라이징 시 문안 넘침·누락을 인쇄 직전에 발견 | 재작업 비용 발생 |
| 규칙 변경 이력이 흩어져 있음 | 어떤 기준으로 승인됐는지 추적 불가 |

참고 사이트 [apbeauty.github.io](https://apbeauty.github.io/)는 **사이드바 기반 섹션 탐색 + 에셋 다운로드**가 강점이지만 "열람" 단계에 머뭅니다. BDOS는 이 탐색 경험을 계승하면서 **관리 → 적용 → 검수 → 제안 → 승인** 단계까지 확장합니다.

## 2. 목표

1. 브랜드 규칙을 **데이터(Rule Set)** 로 관리해 사람·도구가 같은 기준을 사용한다.
2. 패키지·온라인·VMD 시안을 **규칙 기반으로 자동 검수**하고 근거와 수정안을 제시한다.
3. 글로벌 확장(제품군·국가·SKU)이 늘어도 **바이탈뷰티로 일관되게 인식**되도록 한다.
4. 승인 결과와 규칙 변경을 **이력**으로 남긴다.

### 비목표 (이번 범위 아님)
- Illustrator/Figma 대체 편집기 개발
- 법규 해석·법률 자문 (규정 값은 담당 부서 승인값만 입력)
- 완성 디자인을 AI가 최종 산출하는 것 (초안 제안까지만)

## 3. 사용자

| 페르소나 | 주요 목적 | 핵심 기능 |
|---|---|---|
| **브랜드 디자이너** | 가이드 확인, 신규 비주얼 제작 | A, C, B |
| **패키지 디자이너** | 신규 패키지 패밀리룩 검수, 규격 베리에이션 | D, B, E |
| **글로벌 디자인 담당자** | 국가별 문안·규정 대응 | E, A |
| **브랜드 관리자** | 규칙 승인·변경, 최종 승인, 이력 관리 | Rule Admin, 승인 |

## 4. 기능 요구사항

판정 공통 포맷: 모든 검수는 `PASS / WARN / FAIL / N/A(기준 없음)` + **근거 규칙 ID** + **측정값** + **권고**를 반환한다.

|---|---|---|---|

| B-2 | 로고 영역 지정 (수동 박스 / SVG 레이어명 자동) | Rule | P1 |
| B-3 | 로고 크기·위치·컬러·여백 준수 판정 | Rule | P1 |
| B-4 | 대비율(WCAG), 면적비, 배경 복잡도 등 가시성 지표 | Rule | P1 |
| B-5 | 최적 적용안 2~3개 (버전·크기·위치 조합 점수화) | Rule | P1 |

| **B-8** | **Auto Layout**: 규격(유형·W×H mm/px)을 입력하면 로고·제품명 위치·크기를 가이드에 맞게 자동 배치 (2~3안) | Rule (제약 기반 배치) | **P1** |

> B-8은 D의 "규격 베리에이션"과 같은 배치 엔진(`layout-solver`)을 공유한다. 검수(Checker)와 생성(Auto Layout)이 같은 규칙을 반대 방향으로 사용하는 구조.

### C. Visual DNA Generator
| ID | 요구사항 | 방식 | 우선순위 |
|---|---|---|---|
| C-1 | 공통 그래픽·컬러·레이아웃 규칙 관리 | Rule | P2 |
| C-2 | 제품군·적용 매체 선택 | Rule | P2 |
| C-3 | 승인 규칙 기반 초안 생성 (템플릿 + 파라미터 조합 SVG) | Rule | P2 |
| C-4 | 공통(locked) / 가변(variable) 요소 구분 표시 | Rule | P2 |
| C-5 | 생성물·외부 SVG 규칙 준수 검수 | Rule | P2 |
| C-6 | 이미지형 무드/그래픽 초안 생성 | **AI(선택)** | P3 |
| **C-7** | **기존 제품 데이터 학습**: 승인 그래픽·아이콘 SVG에서 형태·선·코너·비율·컬러 파라미터를 통계로 추출해 DNA 규칙 초안 생성 | Rule (SVG 파라미터 통계) | P2 |
| **C-8** | 추출된 DNA로 기존과 비슷한 룩의 신규 그래픽·아이콘 생성 (기능 키워드 → 기본 도형 조합 + DNA 적용) | Rule | P2 |
| C-9 | 기존 룩을 학습한 생성형 모델로 신규 그래픽 생성 (스타일 레퍼런스/파인튜닝) | **AI(선택)** | P3 |

> "학습"의 1차 구현은 **ML 학습이 아니라 승인 SVG의 수치 통계 추출**이다 (예: stroke 평균 1.5px, radius 2px, 원/캡슐 비율 70%). 승인 아이콘이 수십 개 이상 확보되고 Rule 생성 결과가 부족할 때만 C-9를 검토한다.

### D. Package Family-look Checker — **PoC 1순위**
| ID | 요구사항 | 방식 | 우선순위 |
|---|---|---|---|
| D-1 | 승인 패키지 라이브러리에서 기준 선택 + 신규 패키지 등록 | Rule | P0 |
| D-2 | 로고 정합성 (상대 크기·위치·버전) | Rule | P0 |
| D-3 | 컬러 정합성 (라인 컬러 ΔE2000, 톤 밴드, 기존 라인과 겹침) | Rule | P0 |
| D-4 | 제품명 정합성 (서체·상대 크기·위치) | Rule | P0 |
| D-5 | 그래픽 정합성 (규격별 비례, 허용 오차) | Rule | P0 |
| D-6 | 레이아웃 정합성 (존 앵커, 여백, 정렬) | Rule | P0 |
| D-7 | 위반 영역 시각화 (오버레이 박스 + 번호) | Rule | P0 |
| D-8 | 결과 리포트 + 수정 권고안 (예: 추천 컬러칩) | Rule | P0 |
| D-9 | 제품군별 다른 룰셋 적용 | Rule | P0 |
| **D-10** | **Pantone 이력 분석**: 기존 승인 패키지에 사용된 Pantone 번호를 라인·제품군·연도별로 수집·시각화 | Rule | **P0** |
| **D-11** | **Pantone 제안**: 기존 사용 번호와 ΔE 기준 이상 떨어지면서, 제품 베네핏(예: 보습·진정·브라이트닝)을 표현하는 색상 영역 안의 Pantone 후보 3~5개 제안 | Rule | **P0** |
| D-12 | 제안 근거 표시: 최근접 기존 칩·ΔE, 베네핏 컬러 영역 적합도, 브랜드 톤 밴드 적합 여부 | Rule | P0 |

> [!WARNING]
> **D-11 전제 조건**
> 1. **Pantone 색상 데이터는 라이선스 대상**이라 임의로 내장할 수 없다. 사내 보유 라이선스(Pantone Connect 등)의 Lab 값 export 또는 디자인팀 보유 칩 목록을 받아야 한다. 확보 전에는 샘플 칩 목록으로만 데모.
> 2. **베네핏 ↔ 컬러 영역 매핑**(예: 보습 = 블루~아쿠아, Hue 180–230°)은 브랜드가 승인한 값만 사용한다. 미승인 시 매핑은 `DEMO` 표시.
> 3. 화면 RGB와 인쇄 칩은 다르므로 최종 확정은 실물 칩 확인을 전제로 한다.

## 5. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 성능 | 패키지 1건 검수 결과 3초 이내 (브라우저 내 처리) |
| 환경 | 데스크톱 1440px 우선, 1024px·모바일은 열람 중심 반응형 |
| 보안 | 미공개 패키지 업로드 → MVP는 **브라우저 내 처리, 서버 미전송** |
| 비용 | MVP 외부 유료 API 0건 |
| 신뢰성 | 모든 판정에 근거 규칙 ID·측정값 표시, 블랙박스 판정 금지 |
| 접근성 | WCAG 2.1 AA 대비, 키보드 탐색 |

## 6. 데이터 원칙

> [!IMPORTANT]
> - **실제 브랜드 데이터 확보 전에는 모든 값을 `sample: true` 샘플 데이터로 표기**하고 UI에 "SAMPLE" 배지를 노출한다.
> - 법규 기준값(최소 폰트, 필수 문안 등)은 **RA/법무 승인 값만 입력**하며, 출처·승인일이 없는 값은 검수에 사용하지 않는다(`N/A` 처리).
> - 현재 레포의 `src/data/governance.js`에 있는 규정 수치는 **검증되지 않은 프로토타입 값**이므로 샘플로 격리하거나 제거해야 한다.

## 7. 성공 지표 (PoC 기준)

| 지표 | 목표 |
|---|---|
| D 검수와 디자이너 수동 판정 일치율 | ≥ 85% (샘플 20건 기준) |
| 패키지 1건 검수 소요 시간 | 수동 대비 50% 단축 |
| 위반 지적의 근거 표시율 | 100% |
